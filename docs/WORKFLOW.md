# 내 워크플로우 (2026-08-13 개편 후)

## 1. 어디서 무엇을 하는가

| 폴더 | 무엇 | 판정 |
|---|---|---|
| `~/Desktop/Projects/<이름>/` | 마감·제출·발표가 있는 것 | **폴더 하나 = 산출물 하나** |
| `~/Desktop/Career/` | 끝이 없는 것 (진로·이력·영업) | roadmap |

| `~/Software/` | 설치파일 등 작업물 아닌 것 | 체계 밖 |
| 외부 볼트(미러 대상) | "무엇을 하고 있었나" / "무엇을 아는가" | memory 미러·지식 위키 (읽기 전용) |

### 30초 판정 트리
```
마감·제출·발표가 있나?   → Projects/<이름>/
끝없이 굴러가나?         → Career/
에이전트 설정인가?       → ~/Ops/
작업물이 아닌가?         → Inbox/(2주) 또는 ~/Software/
두 프로젝트에 걸치나?     → 태어난 쪽이 원본, 다른 쪽엔 링크 문서만
```

## 2. 지켜야 할 것 3가지 — 어기면 기억이 갈라진다

1. **세션은 항상 프로젝트 루트에서 연다.** 서브폴더에서 열면 memory 키가 따로 생긴다
2. **폴더명은 생성 시 확정. 개명 금지.** memory가 경로에 묶여 있어 개명 = 기억 전량 고아
3. **프로젝트 루트 폴더명은 ASCII 소문자·숫자·하이픈만.** (하위 파일명은 자유, 한글 무방)

셋 다 `SessionStart` 가드가 자동으로 경고한다. 막지는 않는다.

## 3. 새 프로젝트 시작하기

**터미널에서** — 만들고 그 폴더로 이동까지 한 번에:
```bash
newproj kcc-2026-talk deck        # 종류: dev(기본) | deck | hwp | paper | career
```
이름 규칙(ASCII 소문자·숫자·하이픈)을 어기면 **만들어지지 않는다.** 개명이 불가능하므로 여기서 막는다.
과거에 같은 경로를 쓴 적이 있으면 옛 memory가 남아 있다고 알려준다.

**Orca에서 폴더를 만들었다면** — 아무것도 안 해도 된다.
그 폴더에서 세션을 처음 열면 `CLAUDE.md`와 `AGENTS.md`가 **자동 생성**되고 그 사실을 알려준다.
자동 생성이 싫으면 `touch ~/Ops/.no-autoheal` 하면 경고만 하고 만들지 않는다.

그 다음 `AGENTS.md`에 3~6줄로 **매번 어기기 쉬운 것 / 어기면 되돌리기 어려운 것**만 적는다.
프로젝트 소개는 2~3줄. 형식 규칙은 복사하지 말고 `~/Ops/domains/*.md` 경로로 참조만.

### 터미널 단축키 (`~/.zshrc`)
| | |
|---|---|
| `newproj <이름> [종류]` | 새 프로젝트 생성 + 이동 |
| `proj <이름>` | 기존 프로젝트로 이동 |
| `ops` | `~/Ops` 로 이동 |

## 4. 컨텍스트가 어떻게 전달되는가

```
~/Ops/AGENTS.md ──심링크── ~/.claude/CLAUDE.md      모든 세션에 자동 주입
        │
        ├─ ~/Ops/domains/deck.md   pptx 작업 시
        ├─ ~/Ops/domains/hwp.md    hwpx 작업 시
        ├─ ~/Ops/domains/web.md    웹·앱 개발 시
        ├─ ~/Ops/domains/paper.md  논문 작업 시
        └─ ~/Ops/domains/review.md 검증받을 때

<프로젝트>/CLAUDE.md ──@import── <프로젝트>/AGENTS.md   그 프로젝트에서만 주입
~/.claude/projects/<키>/memory/*.md                    자동 축적·자동 주입
```

**규칙은 스킬이 아니라 문서로 전달한다.** 스킬은 사람이 명시 호출할 때만 쓴다
(`hwpx-edit`, `pptx-from-layouts`, `gstack`, `kesekit`).

## 5. 기억은 어디에 쌓이나

- **원본**: `~/.claude/projects/<키>/memory/*.md` — Claude가 자동으로 쓰고 자동으로 읽는다
- **사본**: 외부 볼트(미러 대상) — 세션 종료 시 자동 미러. **여기서 편집하지 말 것**(다음 미러에 덮어써진다)
- Obsidian에서 그래프 뷰를 열면 프로젝트들이 `[[위키링크]]`로 엮인 게 보인다

## 6. 되돌리기 어려운 일을 할 때

```
결제·정산 / 삭제 / 외부 발송 / 외부 게시·배포 / 권한 변경
→ 실행 전 사람 확인. 예외 없음
```
설계·큰 구현은 확정 직전에 **다른 벤더 모델(예: 다른 회사 CLI)** 로 검증받는다. 절차는 `~/Ops/domains/review.md`.
자기검토는 검증으로 치지 않는다.

## 7.5 루프와 그래프 — 실제로 돌리는 법

**루프 (뭔가 바꿨을 때 망가졌는지 확인)**
```bash
~/Ops/bin/loop-run.sh 2026-09-01-<무엇을바꿨나>   # 수집 + 채점표 생성 (10~20분)
# → 채점표 열어서 ? 를 O/X 로 바꾸고 저장
~/Ops/bin/loop-score.sh 2026-09-01-<무엇을바꿨나>  # 채점 → 직전과 비교 → 회귀 경고
```
회귀가 뜨면 방금 바꾼 걸 되돌리고 다시 잽니다. **한 번에 하나만 바꿔야** 원인을 알 수 있습니다.

**그래프 (되돌리기 어려운 것을 확정하기 전)**
```bash
~/Ops/bin/graph-verify.sh <대상경로> "무엇을 검증하는가"
```
```
[사람] 문제정의 → [Claude] 구현 → [다른 벤더 모델] 검증 → 루프백(상한 2회) → [사람] 판정 → 승인 게이트
```
다른 벤더 모델이 반박하고, 고치고, 다시 돌립니다. **2회를 넘기면 스크립트가 멈추고 사람에게 넘깁니다.**
상한을 늘리지 마세요 — 검증은 무한히 새 지적을 만들어냅니다. 무엇을 수용하고 무엇을 기각할지는 사람 몫입니다.
판정 결과는 대상 문서에 표로 남기고, 되돌리기 어려운 결정이면 `~/Ops/adr/`에 적습니다.
