# 검증 절차

자기검토는 검증으로 치지 않는다. 같은 벤더 모델끼리는 편향을 공유한다.

## 언제 다른 벤더를 부르는가
- 되돌리기 어려운 변경 (스키마·마이그레이션·배포·삭제)
- 설계 문서 확정 직전
- 4시간 이상 들인 구현의 완료 직전

## 어떻게
`codex exec` 에 아래를 포함한 프롬프트를 준다.
1. 읽어야 할 파일 경로
2. **"동의하지 말고 반박하라"** 는 명시
3. 사실오류 / 실패 시나리오 / 빠진 것 / 과잉설계 를 나눠서 질문

## 상한
지적사항 반영 루프는 **2회까지**. 초과하면 사람이 판정한다.

## 반영 원칙
- 검증 가능한 주장은 **동의하기 전에 직접 실측한다.** (실제 사례: 교차검증 도구가 키 충돌 위험을 지적 →
  규칙상 사실이나 실측 결과 이 환경은 0건 → 검사 항목으로만 편입하고 설계는 유지)
- 수용·기각 판정을 대상 문서에 표로 남긴다
- **측정이 침묵해도 실사는 계속한다.** 골든셋 점수가 6/6으로 고정된 구간에서
  실사가 심각한 결함 3건을 찾아낸 사례가 있다
